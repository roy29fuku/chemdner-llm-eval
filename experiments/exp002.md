# Experiment 002: Responses API vs Chat Completions API

## 概要

- **日時**: 2026-01-25 11:41〜11:43
- **目的**: GPT-5.2のResponses APIが精度向上に寄与するか検証
- **仮説**: Responses APIは5%程度の精度向上が期待できる（OpenAI公式情報）

## 実験設定

### 比較対象
| 項目 | Exp001 (ベースライン) | Exp002 |
|------|----------------------|--------|
| モデル | GPT-5.2 | GPT-5.2 |
| API | Chat Completions | Responses API |
| プロンプト | Few-shot (4例) | Few-shot (4例) |

### Responses APIの期待効果（公式情報）
- TAUBenchで+5%
- 40-80%高いキャッシュ利用率
- Chain-of-Thought保持

## 結果

| API | Micro-P | Micro-R | Micro-F1 | TP | FP | FN |
|-----|---------|---------|----------|------|------|------|
| Chat Completions | 0.7307 | 0.7060 | 0.7182 | 10474 | 3860 | 4361 |
| **Responses API** | 0.7256 | 0.7062 | 0.7158 | 10477 | 3962 | 4358 |

### 差分
- **Micro-F1**: -0.24pt（Responses APIが若干低い）
- **Precision**: -0.51pt
- **Recall**: +0.02pt（ほぼ同等）

## 考察

### 期待効果が出なかった理由

1. **単一ターンタスク**
   - Responses APIの強み（CoT保持、マルチターン）が活きない
   - 今回は1回のAPI呼び出しで完結

2. **NERタスクの性質**
   - 推論よりも認識（パターンマッチング）が中心
   - TAUBenchのような推論タスクとは異なる

3. **統計的誤差**
   - 0.24ptの差は誤差範囲内の可能性

### 結論

**CHEMDNERタスクにおいて、Responses APIはChat Completions APIと同等の性能。**
マルチターン推論が不要なタスクでは、シンプルなChat Completions APIで十分。

## 実行コマンド

```bash

  --parallel 50 \
  --models gpt-5.2 \
  --api responses \
  --output-dir outputs/exp002_responses_api \
  -y

  --input-dir outputs/exp002_responses_api
```
